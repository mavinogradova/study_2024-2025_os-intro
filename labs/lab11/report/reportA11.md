# Цель работы

Приобретение практических навыков по настройке удалённого доступа к серверу с помощью SSH.

# Задание

1. Настройте запрет удалённого доступа на сервер по SSH для пользователя root (см. раздел 11.4.1).
2. Настройте разрешение удалённого доступа к серверу по SSH только для пользователей группы vagrant и вашего пользователя (см. раздел 11.4.2).
3. Настройте удалённый доступ к серверу по SSH через порт 2022 (см. раздел 11.4.3).
4. Настройте удалённый доступ к серверу по SSH по ключу (см. раздел 11.4.4).
5. Организуйте SSH-туннель с клиента на сервер, перенаправив локальное соединение с TCP-порта 80 на порт 8080 (см. раздел 11.4.5).
6. Используя удалённое SSH-соединение, выполните с клиента несколько команд на сервере (см. раздел 11.4.6).
7. Используя удалённое SSH-соединение, запустите с клиента графическое приложение на сервере (см. раздел 11.4.7).
8. Напишите скрипт для Vagrant, фиксирующий действия по настройке SSH-сервера во внутреннем окружении виртуальной машины server. Соответствующим образом внесите изменения в Vagrantfile (см. раздел 11.4.8).

Выполнение работы производится в соответствии с методическими указаниями [1]. На сервере задаем пароль для пользователя root, если этого не было сделано ранее: `sudo -i`, `passwd root` (рис. [-@fig:001]).

![Задание пароля для пользователя root](/home/mavinogradova/skreens/lbA11/1.png){#fig:001 width=70%}

Пояснение: при этом происходит успешная аутентификация, так как по умолчанию в конфигурации sshd разрешен вход для суперпользователя. Система запрашивает пароль и пускает в оболочку.

На сервере в конфигурационном файле `/etc/ssh/sshd_config` задаем параметр, разрешающий аутентификацию по ключу: `PubkeyAuthentication yes` (рис. [-@fig:018]).

![Включение аутентификации по ключу](/home/mavinogradova/skreens/lbA11/18.png){#fig:018 width=70%}

После сохранения изменений перезапускаем sshd (рис. [-@fig:019]).

![Перезапуск sshd](/home/mavinogradova/skreens/lbA11/19.png){#fig:019 width=70%}

На клиенте формируем SSH-ключ, введя в терминале под нашим пользователем: `ssh-keygen` (рис. [-@fig:020]). Нажимаем Enter на все вопросы, чтобы использовать установку без пароля. Закрытый ключ записывается в `~/.ssh/id_rsa`, открытый — в `~/.ssh/id_rsa.pub`. Данный метод аутентификации является более безопасным по сравнению с парольным доступом [2].

В каталоге `/vagrant/provision/server` создаем исполняемый файл `ssh.sh` и прописываем в нём скрипт (рис. [-@fig:031]).

![Редактирование скрипта ssh.sh](/home/mavinogradova/skreens/lbA11/31.png){#fig:031 width=70%}

Полный текст файла `/vagrant/provision/server/ssh.sh`:

```bash
#!/bin/bash

echo "Provisioning script $0"

echo "Copy configuration files"
cp -R /vagrant/provision/server/ssh/etc/* /etc
restorecon -vR /etc

echo "Configure firewall"
firewall-cmd --add-port=2022/tcp
firewall-cmd --add-port=2022/tcp --permanent

echo "Tuning SELinux"
semanage port -a -t ssh_port_t -p tcp 2022

echo "Restart sshd service"
systemctl restart sshd
```

Для отработки созданного скрипта во время загрузки виртуальной машины server в конфигурационном файле Vagrantfile добавляем в разделе конфигурации для сервера соответствующие строки (рис. [-@fig:032]).

# Ответы на контрольные вопросы

1. **Вы хотите запретить удалённый доступ по SSH на сервер пользователю root и разрешить доступ пользователю alice. Как это сделать?**
Для этого необходимо в файле `/etc/ssh/sshd_config` установить параметр `PermitRootLogin no` (запрет для root) и добавить директиву `AllowUsers alice` (разрешение только для alice). После внесения изменений требуется перезапустить службу командой `sudo systemctl restart sshd`.

2. **Как настроить удалённый доступ по SSH через несколько портов? Для чего это может потребоваться?**
В файле `/etc/ssh/sshd_config` нужно добавить несколько строк `Port` (например, `Port 22` и `Port 2022`). Это может потребоваться для обеспечения резервного доступа на случай ошибки в конфигурации одного из портов, для обхода ограничений межсетевых экранов, а также для разделения пользовательского и административного трафика.

3. **Какие параметры используются для создания туннеля SSH, когда команда ssh устанавливает фоновое соединение и не ожидает какой-либо конкретной команды?**
Для этого используются ключи:
- `-f` — переход в фоновый режим;
- `-N` — не выполнять удаленную команду (только проброс портов);
- `-L` — локальная переадресация портов.
Пример: `ssh -fNL 8080:localhost:80 user@host`. [2].

4. **Как настроить локальную переадресацию с локального порта 5555 на порт 80 сервера server2.example.com?**
Необходимо использовать команду с ключом `-L`:
`ssh -L 5555:server2.example.com:80 user@<промежуточный_хост>`
Это создаст туннель, при котором подключение к локальному порту 5555 будет перенаправляться на порт 80 указанного сервера через промежуточный хост.

5. **Как настроить SELinux, чтобы позволить SSH связываться с портом 2022?**
Необходимо использовать утилиту `semanage` для добавления порта в контекст безопасности ssh:
`sudo semanage port -a -t ssh_port_t -p tcp 2022`
Это разрешит демону sshd прослушивать нестандартный порт.

6. **Как настроить межсетевой экран на сервере, чтобы разрешить входящие подключения по SSH через порт 2022?**
Необходимо использовать утилиту `firewall-cmd`:
`sudo firewall-cmd --add-port=2022/tcp`
`sudo firewall-cmd --add-port=2022/tcp --permanent`
Первая команда добавляет правило в текущую сессию, вторая — сохраняет его для применения после перезагрузки.
